## 信创
- **X86 架构**
  - Intel / AMD CPU
  - Windows/Linux 支持完善
  - 软件生态成熟（Oracle、MySQL、Redis、各种框架）
- **信创环境**（国产化、信创指“信息技术应用创新”）
  - CPU：飞腾、鲲鹏、龙芯
  - OS：统信 UOS、银河麒麟
  - 中间件：国产 Oracle 替代（人大金仓、达梦）、Redis 兼容版本等
  - 框架/库：部分开源或国产替代，兼容性可能存在差异

|维度|X86 架构|信创环境|
|---|---|---|
|**CPU 架构**|x86_64|ARM / Loongson / 飞腾|
|**系统指令集**|x86 指令|ARM 指令 / MIPS 指令（根据国产CPU）|
|**操作系统生态**|Linux/Windows 完全成熟|Linux国产发行版（UOS、银河麒麟）|
|**中间件兼容性**|官方支持 Oracle/MySQL/Redis 等|有国产替代，兼容性需验证|
|**编译器/二进制**|GCC/Clang/Intel编译器|GCC/Clang可用，但部分依赖需重新编译|
|**性能优化**|针对 x86 指令优化成熟|需要针对 ARM/国产CPU优化（例如 SIMD、缓存行）|
|**软硬件适配**|即插即用，Docker/K8s 支持完善|容器化和微服务可行，但镜像需重新构建或适配|
|**安全规范**|商业生态成熟|信创要求国产安全规范，有时需要加密模块适配|
|**运维工具链**|Ansible/Puppet/监控成熟|可能有国产运维替代，需评估兼容性|

### TongWeb
- JEE 容器
- Tomcat 区别

- **Tomcat 胜在“灵活性”：** 如果你的项目是中小型互联网应用、互联网架构、或者是追求极致轻量化的微服务，Tomcat 的性能上限足够高，且调优资料极其丰富。
- **TongWeb 胜在“稳定性与合规”：** 在**千万级表查询**和**高并发金融交易**场景下，TongWeb 的商业支持能解决很多深层内核阻塞问题。此外，如果你面临等保三级、信创国产化替代的要求，TongWeb 的性能优化是开箱即用的，省去了大量手动压测调优的时间。

“切换信创过程中主要存在**兼容性、性能、运维和安全**四类问题。企业通常采用**分阶段迁移 + 兼容适配层 + 双环境验证 + 多平台 CI/CD + 性能监控优化**的机制来保证业务平滑迁移。在架构设计上，需要抽象中间件接口、适配国产 CPU/OS 特性，同时保证安全合规和可扩展性。”

- 灰度迁移策略（避免一次性切换风险）
- 容器多平台镜像（x86 + ARM/国产CPU）
- 数据库/缓存/消息中间件抽象接口（可替换国产方案）
- 国产加密模块（SM2/SM3/SM4）替换策略

2️⃣ 兼容层（适配机制）
- **中间件适配**
  - DB/缓存/MQ 替换国产版本
  - DAO / Repository 层抽象，统一接口
- **指令集兼容**
  - 编译源代码或跨平台二进制（Java、Go、Python 可跨平台）
  - x86 原生库 → ARM/国产CPU重编译或替换
- **容器化适配**
  - Docker multi-arch 镜像（x86 + ARM64）
  - Kubernetes 部署策略调整


### 双写判断是否一致
- **数据对账表 / 对账服务**
- **实时指标 + 可视化面板**
- **告警与异常提示**
- **操作权限与自助修复**
  1️⃣ 数据对账表 / 对账服务
- 定时扫描数据差异
- 生成“未消费、异常、延迟”列表
  2️⃣ 实时指标 & 可视化
  **监控指标**：
- 消息堆积量（Lag）
- 消费状态（成功/失败）
- 从库落后指标
- 业务状态一致性指标
  3️⃣ 告警与异常提示
- 对业务操作人员：
  - 异常订单或消息直接高亮
  - 支持邮件 / 微信 / 钉钉告警
- 对运维：
  - 系统堆积或消费延迟告警
    4️⃣ 可操作功能
- **重试 / 补偿操作**：
  - 对单条或批量异常数据提供操作按钮
  - 自动重新消费 / 补偿写入
- **异常明细钻取**：
  - 可以查看每条消息或订单的 MQ TraceId、消费状态、异常原因
    5️⃣ 设计模式与技术实现
1. **数据埋点 + TraceId**
  - MQ 消息、业务操作、数据库操作全打上 **TraceId**
  - 对账表根据 TraceId 聚合，保证可追踪
2. **事件驱动 + 近实时同步**
  - MQ 消息落库 → 对账表实时更新
  - 从库同步慢 → 对账服务计算延迟差异
3. **灰度 / 采样策略**
  - 高流量系统可以只对部分关键业务做可视化，降低压力

- TraceId 全链路追踪，保证可追踪性
- 异常明细可钻取，支持单条/批量补偿
- Grafana/Kibana 或自研 Dashboard 可视化
- 对业务操作人员和运维人员分角色展示不同视图
